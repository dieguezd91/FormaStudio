# Scenario 13.1 end to end

A game that already has an item system imports a Forma export, connects it with one adapter, and keeps its own work when the
design changes and is exported again. `npm run e2e:unity` runs the whole chain against a real Unity editor.

## What is automated

`e2e/unity/run-13-1.ts` runs these steps and prints a PASS/FAIL table (exit code is non-zero on any failure):

1. Copies `unity/com.forma.studio/Samples~/ExistingInventory` into `unity/FormaSandbox/Assets/Samples/ExistingInventory` (fresh copy)
   and cleans `Assets/FormaStudio/Generated/E2E/` in the sandbox.
2. Starts the local service in-process (`buildServer`, temp data dir, `127.0.0.1`, free port). Everything below goes through HTTP, like
   the desktop app.
3. Creates the project «Inventario 13.1», inserts the library entries `inventory.tabs` and `inventory.equipment` (weapon and head
   slots) with `insertEntry`, applies a style batch (`colors.surface`, `colors.accent`) and checks that every slot has the
   `contextMenu` behavior.
4. Analyzes compatibility (counts are recorded), installs the package into the sandbox (idempotent) and exports to
   `Assets/FormaStudio/Generated/E2E`.
5. Runs Unity (`-runTests`, category `E2E13_1`, fixture `Forma13_1_FirstImport`): import, the game's items through the adapter, the
   game's accept/reject decisions, and a developer customization saved into the Prefab.
6. Changes the design with batches (`colors.surfaceAlt`, renames «Título» to «Mochila», adds a «Peso total» text node) and exports
   again; the response must carry a non-empty diff (added / changed / renamed counts are recorded).
7. Runs Unity with `Forma13_1_Reimport`: the design changes are applied and the adapter, wiring, `DevBadge` and the developer's
   serialized field survive.

Two details of the Unity side shape the script:

- `Forma13_1_FirstImport` deletes `Assets/FormaStudio/Generated/E2E`, so the exported V1 is staged in
  `e2e/unity/artifacts/v1/` and passed as `FORMA_E2E_BUNDLE`.
- `Forma13_1_Reimport` needs V1 and its Prefab still in the sandbox, so V2 is exported into a throwaway Unity project
  (`e2e/unity/artifacts/v2-project`, same output folder, hence the same file name) and passed as `FORMA_E2E_BUNDLE_V2`. The fixture
  reads the design changes from the difference between the two bundles; `FORMA_E2E_V2_SURFACE_ALT` carries the new color of the
  `surfaceAlt` token.

Output goes to `e2e/unity/artifacts/` (git-ignored): `first.xml|log`, `second.xml|log` (Unity), `v1/`, `v2/` (staged bundles) and
`report.json` (steps, compatibility counts, diff counts, Unity counts).

## What is NOT automated

- **AI generation.** There is no Gemini key in this environment. The design is composed from the library, which is the same path AI
  proposals compile into (`insertEntry` batches applied through `/document/batches`).
- **Real pointer input.** The fixtures raise the same intents the Forma components raise (`FormaIntent` on the screen); they do not
  simulate a mouse dragging or right-clicking.
- **Visual appearance and TextMeshPro Essentials.** Nothing renders a frame; text is checked through `TMP_Text.text` and colors
  through component values. Whether the TMP Essential Resources are imported is not checked.
- One pre-existing flaky test in the package's own suite,
  `Postprocessor_ImportsAnImportedBundleOnceTheImportHasFinished`, is not part of category `E2E13_1` and is not run here.

## How to run

```bash
npm run e2e:unity
```

Requirements: Node >= 22.13, the sandbox (`unity/FormaSandbox`) not open in another Unity instance, and Unity 6000.0.73f1 at
`C:/Program Files/Unity/Hub/Editor/6000.0.73f1/Editor/Unity.exe`, or set `UNITY_EDITOR` to another editor executable. Each Unity run
has a 15 minute limit; the first one can take longer because the sandbox compiles.

To run only the Unity fixtures, see «Scenario 13.1 end-to-end» in `unity/FormaSandbox/README.md`.

## Manual Unity checklist

Things the script cannot see. Run the script first (or export from the desktop app) so `Assets/Samples/ExistingInventory` and the
bundle are in the sandbox.

1. Copy the sample if needed: `unity/com.forma.studio/Samples~/ExistingInventory` into `unity/FormaSandbox/Assets/Samples/`.
2. Open `unity/FormaSandbox` in Unity 6000.0 and let the bundle in `Assets/FormaStudio/Generated/E2E` import (the Prefab appears
   next to it). Import TMP Essentials if Unity asks.
3. `Tools/Forma Studio/Create Canvas` to put a Canvas (and EventSystem) in the scene, then drag the Prefab under it.
4. Add the sample's `PlayerInventoryFormaAdapter` to the Prefab root and attach it as the screen's data source and intent handler.
5. Press Play. Check that the tabs show the game's items (weapons, armor, potions, key) and no mock data.
6. Drag items between slots and onto the weapon / head equipment slots: the matching item equips; a mismatched slot or a level that
   is too low is rejected and the UI does not change.
7. Right-click a slot and choose **Usar** on a potion (the count drops); try **Soltar** on the quest key and see the game's refusal.
8. Look at the result: colors, spacing, tab switching and text legibility are what the design intended.
